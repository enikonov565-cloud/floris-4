# Бриф на сайт

Пошаговая анкета для клиентов: 7 этапов по 3–5 вопросов, автосохранение черновика, загрузка файлов, отправка ответов в Telegram.
Статика без сборки: HTML + CSS + JS. Лежит в отдельной папке `brief/` и с основным сайтом не связана.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка: шапка, интро, контейнер этапов, финал, подвал |
| `styles.css` | оформление; цвета и радиусы — токены в `:root` в начале файла |
| `app.js` | логика; **вопросы и данные о вас — массивы в начале файла** |
| `config.js` | только адрес приёмника (Cloudflare Worker) |
| `worker.js` | код для Cloudflare — на сайт не выкладывается, вставляется в Cloudflare |
| `fonts/` | шрифт Manrope (лицензия OFL) |
| `img/` | сюда положить вашу фотографию для финального экрана |

## Первым делом: заполнить данные о себе

Откройте `app.js`, блок `SITE` в самом начале:

```js
const SITE = {
  brand: 'Бриф',                       // текст в шапке
  owner: 'Ваше имя',
  photo: 'img/photo.jpg',              // положите фото в brief/img/photo.jpg
  telegram: 'https://t.me/username',
  replyDays: '2 рабочих дней',
  legal: [ { title: 'Политика конфиденциальности', href: 'https://…' }, … ],
  requisites: 'ИП … · ИНН … · ОГРНИП …'
};
```

- **Юридические документы.** В `legal` вставьте ссылки на политику, согласие и оферту с вашего сайта. Первые два документа автоматически попадают в текст чекбокса согласия на этапе «Контакты».
- **Фото.** Пока файла нет, на финальном экране показывается первая буква имени.

## Как менять вопросы

Все вопросы — массив `QUESTIONS` в `app.js`. Каждый вопрос — объект:

```js
{ id: 'sale_break',        // уникальное имя латиницей, по нему хранится ответ
  stage: 'sales',          // к какому этапу относится (id из массива STAGES)
  label: 'Где сделки чаще всего рвутся?',
  hint: 'Подсказка под вопросом',   // можно ''
  required: true,          // обязательный
  key: true,               // плашка «важно» и выделение карточкой
  summary: true,           // попадёт в первое сообщение-сводку в Telegram
  type: 'textarea' }       // textarea (по умолчанию) | text | links | files | consent
```

- Добавить вопрос — вставить объект в нужное место массива.
- Добавить этап — добавить строку в `STAGES` и вопросы с этим `stage`. Счётчик «01 / 07», точки и прогресс пересчитаются сами.
- Если поменяли `id` у вопросов, увеличьте версию в `DRAFT_KEY` (`'brief-draft-v2'`), чтобы старые черновики не подтягивались.

## Как работает отправка

1. Человек нажимает «Отправить» на этапе «Контакты» (без галочки согласия кнопка не сработает).
2. Если в `config.js` адрес **пустой** — скачивается файл `brief-ДАТА.txt` с ответами, финальный экран просит прислать его вам в Telegram.
3. Если адрес задан — ответы уходят в Worker, затем каждый файл отдельным запросом.
4. **При любой ошибке** ответы скачиваются файлом и остаются в черновике браузера, на экране — кнопка «Отправить ещё раз». После успешной отправки черновик очищается.

Черновик: тексты — в `localStorage`, файлы — в `IndexedDB` (переживают закрытие вкладки). Галочка согласия намеренно не сохраняется — её ставят заново.

## Подключение Telegram-бота

### 1. Создать бота
1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя.
2. Сохраните **токен** вида `123456:ABC-…`.
3. Напишите своему боту любое сообщение (иначе он не сможет вам писать).

### 2. Узнать CHAT_ID
- Себе в личку: напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш id.
- В группу: добавьте бота в группу, отправьте там сообщение, откройте
  `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — id группы начинается с `-100…`.

### 3. Создать Worker в Cloudflare
1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → **Create Worker** → **Deploy**.
2. **Edit code** → удалите шаблон, вставьте содержимое `worker.js` → **Deploy**.
3. **Settings → Variables and Secrets** → добавьте:
   - `BOT_TOKEN` — токен бота (тип **Secret**);
   - `CHAT_ID` — ваш id или id группы;
   - `ALLOWED_ORIGINS` — необязательно, адрес сайта, например `https://username.github.io` (без пути). Тогда чужие сайты не смогут слать вам заявки.
4. Скопируйте адрес воркера (`https://….workers.dev`).

### 4. Вписать адрес в config.js

```js
window.BRIEF_CONFIG = {
  endpoint: 'https://brief-bot.username.workers.dev'
};
```

Готово. Проверьте: заполните бриф и отправьте — в Telegram придут сообщения.

### Как выглядят сообщения в Telegram
- **Первое — сводка:** имя, компания, контакт и ответы на вопросы с `summary: true` (сокращены до ~350 символов).
- **Дальше — по сообщению на этап**, вопросы жирным. Незаполненные вопросы и пустые этапы не отправляются.
- Длинные ответы режутся по абзацам, затем по предложениям — с учётом лимита Telegram 4096 символов. Продолжение помечено «— продолжение».
- Файлы приходят документами с подписью «📎 Имя · контакт».

## Публикация на GitHub Pages

Папка `brief/` открывается по адресу `https://<user>.github.io/<репозиторий>/brief/`.
Если GitHub Pages ещё не включён: репозиторий → **Settings → Pages** → Source: *Deploy from a branch* → ветка `main`, папка `/ (root)`.
